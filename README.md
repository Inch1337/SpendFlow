# SpendFlow

Небольшое веб-приложение для учёта личных расходов, выполненное как тестовое задание.

## Возможности

- Добавление, просмотр и удаление расходов.
- Фильтрация по датам и категории, поиск по описанию.
- Сортировка от новых расходов к старым.
- Общая сумма и разбивка расходов по категориям за выбранный период.
- Диаграмма по категориям и выбор текущего месяца.
- Проверка входных данных и сообщения об ошибках.
- Swagger для просмотра и вызова API.

Интерфейс состоит из одной страницы. Список и статистика обновляются без перезагрузки.
Категория и поиск влияют только на список; статистика учитывает выбранные даты.
Даты в интерфейсе вводятся и отображаются в формате `dd/mm/yyyy`, например `15/01/2026`.
Используется текстовый ввод без встроенного календаря. Перед отправкой в API даты
преобразуются в `YYYY-MM-DD`. Несуществующие даты отклоняются.
Во время сохранения поля формы добавления блокируются; при ошибке введённые данные сохраняются.

## Стек и структура

- Backend: .NET 8, ASP.NET Core Web API, Controllers.
- Данные: EF Core 8, Npgsql, PostgreSQL 16.
- Frontend: HTML, CSS, JavaScript, fetch. Диаграмма реализована средствами HTML/CSS.
- Тесты: xUnit, отдельная PostgreSQL для интеграционных тестов.
- Запуск: Docker Compose.

```text
SpendFlow.Api/
  Controllers/    HTTP endpoints и коды ответов
  DTOs/           Модели запросов, ответов и валидация
  Entities/       Expense и фиксированные категории
  Services/       Работа с расходами, фильтрация и статистика
  Data/           EF Core DbContext
  Migrations/     Миграции PostgreSQL
  wwwroot/        HTML, CSS и JavaScript
SpendFlow.Tests/  Тесты валидации и интеграционные тесты сервиса
```

Запрос проходит через Controller -> ExpenseService -> AppDbContext -> PostgreSQL.
Контроллеры принимают и возвращают DTO. Mapping выполняется явно, без AutoMapper.

## Требования для запуска

- Docker с поддержкой Linux-контейнеров и Docker Compose.
- Для команд на хосте: .NET SDK с поддержкой формата `.slnx`. Проект проверен с SDK 10.0.400.
- Для локального запуска приложения, тестов и EF tools: .NET 8 / ASP.NET Core 8 runtime.
- Инструмент `dotnet-ef` версии 8.0.31 для применения миграций.

Само приложение использует `net8.0`. Dockerfile собирает `.csproj` через SDK 8 и не требует поддержки `.slnx` внутри контейнера.
Все команды ниже выполняются из корня репозитория.

Если `dotnet-ef` ещё не установлен:

```powershell
dotnet tool install --global dotnet-ef --version 8.0.31
```

## Запуск через Docker Compose

Порты `5432` и `8080` должны быть свободны.

### Первый запуск

Поднимите PostgreSQL, примените миграции и запустите API:

```powershell
docker compose up -d --wait postgres
dotnet ef database update --project SpendFlow.Api --connection "Host=localhost;Port=5432;Database=spendflow;Username=postgres;Password=postgres"
docker compose up --build -d
```

Миграции применяются вручную с хоста. API самостоятельно их не применяет.
Healthcheck проверяет готовность PostgreSQL принимать подключения, но не наличие таблиц.
При добавлении новых миграций повторите команду `dotnet ef database update`.

### Адреса приложения

| Назначение | Адрес |
| --- | --- |
| Интерфейс | [http://localhost:8080/](http://localhost:8080/) |
| Swagger | [http://localhost:8080/swagger](http://localhost:8080/swagger) |
| Список расходов API | [http://localhost:8080/api/expenses](http://localhost:8080/api/expenses) |

### Повторный запуск, логи и остановка

Если миграции уже применены:

```powershell
docker compose up --build -d
```

Просмотр логов API:

```powershell
docker compose logs -f api
```

Остановка:

```powershell
docker compose down
```

Рабочие данные сохраняются в volume `spendflow_pgdata`.
Команда `docker compose down -v` удаляет volume вместе с данными.

Compose предназначен для локальной демонстрации: HTTP, без авторизации, с демонстрационными реквизитами БД.
API внутри контейнера подключается к `postgres:5432`, команды с хоста - к `localhost:5432`.

## Локальный запуск API

PostgreSQL остаётся в Docker, приложение запускается через .NET CLI:

```powershell
docker compose up -d --wait postgres
dotnet ef database update --project SpendFlow.Api
dotnet run --project SpendFlow.Api --launch-profile http
```

Строка подключения к локальной БД задана в `SpendFlow.Api/appsettings.json`.

- Интерфейс: [http://localhost:5110/](http://localhost:5110/).
- Swagger: [http://localhost:5110/swagger](http://localhost:5110/swagger).

## API

| Метод | Путь | Назначение | Успешный ответ |
| --- | --- | --- | --- |
| POST | `/api/expenses` | Создать расход | 201, созданный расход и заголовок Location |
| GET | `/api/expenses` | Получить список | 200 |
| GET | `/api/expenses/{id}` | Получить расход | 200 |
| DELETE | `/api/expenses/{id}` | Удалить расход | 204, без тела |
| GET | `/api/expenses/summary` | Получить статистику | 200 |

### Создание расхода

`POST /api/expenses`, заголовок `Content-Type: application/json`:

```json
{
  "description": "Кофе",
  "amount": 150.50,
  "date": "2026-01-15",
  "category": "Food"
}
```

Категории: `Food`, `Transport`, `Housing`, `Entertainment`, `Health`, `Other`.
В JSON категория передаётся строкой.
Ответ расхода содержит `id`, `description`, `amount`, `date`, `category`, `createdAt`, `updatedAt`.
Редактирование не реализовано, поэтому `updatedAt` остаётся `null`.

### Фильтры и статистика

Все параметры необязательны. Фильтры списка применяются совместно:

```http
GET /api/expenses?dateFrom=2026-01-01&dateTo=2026-01-31&category=Food&search=coffee
GET /api/expenses/summary?dateFrom=2026-01-01&dateTo=2026-01-31
```

- `dateFrom` и `dateTo` включают обе границы. Можно указать только одну дату.
- Без дат учитываются расходы за всё время.
- Поиск проверяет вхождение в описание без учёта регистра; пробелы по краям запроса удаляются.
- Символы `%`, `_` и `\` в поиске трактуются буквально.
- Список сортируется по `date` по убыванию, затем по `id` по убыванию.
- Статистика возвращает `totalAmount` и массив `byCategory` с полями `category` и `totalAmount`.
- В статистике присутствуют все шесть категорий, включая категории с нулевой суммой.
- Пустой список возвращается как `[]`; статистика пустого периода содержит нулевые суммы.

Готовые запросы находятся в `SpendFlow.Api/SpendFlow.Api.http`.
Для Docker задайте в нём `SpendFlow.Api_HostAddress = http://localhost:8080`,
для локального запуска - `http://localhost:5110`. Для получения и удаления записи укажите её `expenseId`.

## Валидация и ошибки

- Описание обязательно, не может состоять только из пробелов, максимум 500 символов. Пробелы по краям удаляются при сохранении.
- Сумма одного расхода - от `0.01` до `999999999.99` включительно, до двух знаков после запятой.
- `12`, `12.3`, `12.30` и `12.300` допустимы; `12.345` отклоняется без округления.
- Дата обязательна и передаётся в формате `YYYY-MM-DD`. Будущие даты допустимы.
- Категория обязательна и должна входить в фиксированный список.
- Начальная дата периода не может быть позже конечной.

Ошибки валидации и некорректные параметры возвращают `400`, отсутствующий расход - `404`.
Неожиданные ошибки обрабатываются централизованно с ответом `500` без stack trace и деталей БД.
Создание и удаление логируются через стандартный `ILogger`.

Дата расхода хранится как `DateOnly` / PostgreSQL `date`.
Системные timestamps используют `DateTimeOffset` / `timestamp with time zone`; при создании записывается UTC.

На сервере суммы вычисляются через `decimal`. В интерфейсе отображаются два дробных знака.
Лимит суммы относится к одному расходу, а не к статистике. Браузер использует JavaScript `Number`,
поэтому точность копеек для произвольно больших итогов не гарантируется.
Новые ограничения не изменяют ранее сохранённые записи в БД.

## Сборка и тесты

Сборка решения:

```powershell
dotnet build SpendFlow.slnx
```

### Тесты без БД

Проверяют DTO: обязательные поля, длину описания, диапазон и точность суммы, категории и периоды.

```powershell
dotnet test SpendFlow.slnx --filter "Category!=Integration"
```

### Тесты frontend

Для этих проверок нужен Node.js с поддержкой встроенного `node:test`; установка npm-пакетов не требуется.

```powershell
node --test SpendFlow.Tests/Frontend/app.test.cjs
```

Проверяются календарные даты, фильтры и поведение формы при успешном и неуспешном сохранении.
Тесты выполняются без браузера и сетевых запросов, с подменой DOM и API.
Для запуска самого приложения Node.js не нужен.

### Интеграционные тесты

Вызывают `ExpenseService` с настоящей PostgreSQL 16. Проверяют статистику, границы периода,
совместное применение фильтров, поиск и сортировку. Запускать API для них не нужно.

```powershell
docker compose -f docker-compose.tests.yml up -d --wait
dotnet test SpendFlow.slnx --filter "Category=Integration"
```

Для полного прогона с работающей тестовой БД:

```powershell
dotnet test SpendFlow.slnx
```

Тестовый Compose поднимает только PostgreSQL, а не приложение.
Он использует отдельный проект `spendflow-tests`, порт `55432` и БД `spendflow_tests`.
Рабочая БД и её volume не используются.

Fixture применяет миграции. Каждый тест выполняется в транзакции, которая затем откатывается.
Не запускайте несколько процессов интеграционных тестов одновременно против этой тестовой БД.
Без доступной БД интеграционные тесты завершатся ошибкой, а не пропуском.

После проверки:

```powershell
docker compose -f docker-compose.tests.yml down
```

Тестовая БД хранится в `tmpfs`; данные исчезают при остановке контейнера.
Предупреждение `NU1900` означает, что NuGet не смог получить данные об уязвимостях пакетов.
Оно не является результатом выполнения тестов: смотрите отдельную сводку тестового запуска.

## Ручная проверка

1. Откройте интерфейс, добавьте несколько расходов разных категорий и дат.
2. Проверьте фильтры, поиск, сброс и кнопку «Текущий месяц».
3. Сравните общую сумму и диаграмму с добавленными данными.
4. Удалите расход и убедитесь, что список и статистика обновились.
5. Обновите страницу и проверьте сохранность данных.
6. В Swagger проверьте ошибки: пустое тело, пробельное описание, сумму `0` или `12.345`, дату `2026-02-30`, неверную категорию и обратный период.
7. Проверьте получение и удаление несуществующего расхода: ожидается `404`.

## Границы проекта
